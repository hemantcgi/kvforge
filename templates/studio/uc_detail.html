Phase 1 ● ACTIVE
📄 Text RAG
Answer questions from your documents — no GPU needed
Your documents are split into chunks, embedded as vectors, and stored in a vector database. When a question comes in, the most relevant chunks are retrieved and passed to the LLM as reading context. This is the fastest path to a working question-answering system.
No GPU required ~6 s / query
Not indexed yet
Phase 2 ● ACTIVE
⚡ KV Injection
4× faster answers — pre-computed attention cache
KV (key-value) tensors are pre-computed for every document chunk using your GPU, then stored alongside embeddings. At query time, the LLM reuses these cached tensors instead of re-processing text — skipping the most expensive encoding step entirely.
GPU required ~1.5 s / query
Requires Phase 1 + KV Indexer run
Phase 3 ● ACTIVE
🧠 Parametric
7× faster — model answers from memory
After LoRA fine-tuning on your corpus, the model learns to answer frequently-asked queries directly from its weights — no retrieval or chunk lookup needed. It falls back to KV/text RAG for questions it's not confident about (confidence gate at PRS ≥ 0.75).
GPU required ~0.8 s / query
Requires LoRA training + PRS ≥ 0.75
