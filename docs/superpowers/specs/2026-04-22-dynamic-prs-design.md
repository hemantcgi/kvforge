# Dynamic PRS: Cluster-Aware Three-Signal Calibration

**Date:** 2026-04-22
**Status:** Approved for implementation

---

## Problem

The current Parametric Readiness Score (PRS) has three hardcoded fragilities:

1. **Fixed threshold** — 0.75 applied universally across all use cases and all domains
2. **Fixed advancement rule** — "two consecutive rounds ≥ 0.75" regardless of trajectory or corpus character
3. **Fixed sub-score weights** — accuracy 0.5 / calibration 0.3 / consistency 0.2 regardless of what actually predicts correctness for a given UC
4. **Single signal source** — PRS is calibrated only against an offline FAQ set; it ignores the full VDB knowledge space and real production query traffic

The result: new UCs take too long to advance because the threshold is miscalibrated for their specific corpus, domain, and query distribution.

---

## Core Insight

The VDB is not just a fallback — it is the teacher. Every query the VDB answers is a `(question, retrieved_answer)` training pair the model should learn from. PRS should reflect how much of the VDB's actual knowledge distribution the model has internalized, measured against all three available signals simultaneously:

- **VDB knowledge** — the full semantic space of what the model could know
- **FAQ coverage** — structured offline signal (current, preserved)
- **Real-time queries** — actual production traffic (most honest signal of user intent)

---

## Two Deployment Modes

### Greenfield — KVForge builds the VDB from scratch

Full cluster-aware PRS with per-cluster phase advancement. The primary path for new KVForge deployments.

### Brownfield — Existing VDB, KVForge introduced gradually

Per-chunk confidence scoring with query-time routing. KVForge is introduced with zero disruption to existing retrieval behavior and progressively takes over as the model earns trust chunk by chunk.

A UC starts in brownfield mode when an existing VDB is imported. It can transition to greenfield cluster mode once coverage reaches critical mass.

---

## Architecture

### Greenfield Mode

#### 1. Semantic Clustering (index time)

After all chunks are embedded, run K-means over the embedding space. K is auto-selected by silhouette score (evaluated over K ∈ [3, 20]). Each chunk's VDB payload gains a `cluster_id` field. Cluster centroids are persisted to `clusters.json` per UC.

```json
// clusters.json
{
  "k": 7,
  "centroids": [[...], [...], ...],
  "cluster_labels": ["authentication", "billing", "setup", ...],
  "created_at": "2026-04-22T10:00:00Z",
  "lora_version": 0
}
```

Cluster labels are auto-generated by asking the LLM to summarize the 5 most representative chunks per cluster. They are human-readable but not used in routing logic.

#### 2. Per-Cluster PRS State (version.json)

Each cluster tracks three coverage signals independently:

- `faq_coverage` — fraction of FAQs mapped to this cluster that the model answers correctly (accuracy_ratio ≥ 0.85)
- `vdb_coverage` — fraction of this cluster's chunks the model can answer from weights, sampled each LoRA round (20 chunks per cluster, or all if cluster < 20 chunks)
- `realtime_coverage` — fraction of real-time queries hitting this cluster answered parametrically and not re-queried within 10 minutes (proxy for user satisfaction)

```json
// version.json cluster state
"clusters": {
  "0": {
    "label": "authentication",
    "phase": 2,
    "faq_coverage": 0.82,
    "vdb_coverage": 0.71,
    "realtime_coverage": 0.68,
    "learned_weights": {"faq": 0.38, "vdb": 0.41, "realtime": 0.21},
    "threshold": 0.72,
    "prs_history": [0.61, 0.67, 0.72],
    "query_count": 143
  },
  ...
}
```

#### 3. Adaptive Weight Learning Per Cluster

After each LoRA round, for each cluster with ≥ 10 labeled query outcomes:

1. Collect labeled history: features = `(faq_coverage, vdb_coverage, realtime_coverage)`, label = `correctly_answered` (1 if not re-queried, 0 otherwise)
2. Fit logistic regression (numpy-only, no sklearn dependency)
3. Normalize coefficients to sum to 1.0; clip each to [0.10, 0.70] to prevent degenerate solutions
4. Store as `learned_weights` in cluster state
5. Recompute cluster PRS using new weights

For clusters with < 10 labeled outcomes, use config default weights (`prs_weights` in UC config, default: `{faq: 0.4, vdb: 0.4, realtime: 0.2}`).

#### 4. Advancement Criterion (replaces "two consecutive rounds")

A cluster advances to the next phase when **both** conditions hold simultaneously:

- `cluster_prs ≥ cluster_threshold` (threshold is per-cluster, learned over time)
- `slope(prs_history[-3:]) ≥ 0` (non-negative trend over last 3 rounds — stable or improving)

Initial per-cluster threshold is set as:
```
initial_threshold = base_threshold × difficulty_multiplier
base_threshold = prs_advancement_threshold (config, default 0.72)
difficulty_multiplier = clip(mean_intra_cluster_embedding_distance / global_mean_distance, 0.85, 1.15)
```
High intra-cluster embedding variance → chunks are semantically spread → harder domain → higher threshold. Low variance → tight cluster → easier to master → lower threshold. This requires no external domain classifier; it derives difficulty from the embedding geometry already computed at index time.

After enough labeled query outcomes accumulate (≥ 30 per cluster), the threshold adapts: it is set to the PRS score at which the per-cluster logistic regression classifier achieves ≥ 80% precision on held-out queries (5-fold cross-validation). This replaces the geometry-based estimate with an empirically validated threshold for that cluster.

The per-cluster learned threshold serves a dual purpose: it gates phase advancement AND replaces the global `gate_threshold` for queries routed to that cluster at inference time. This ensures training-time measurement and inference-time routing use the same calibrated bar.

#### 5. Per-Cluster Routing (query time)

```
query → embed → find nearest cluster centroid → check cluster.phase
  phase 3 → parametric answer
  phase 1/2 → retrieval → log (query_embedding, answer, cluster_id, timestamp) as training pair
```

Every retrieval response is a teacher signal. Logged pairs are weighted by cluster query frequency in the next LoRA training round (hot clusters train more).

#### 6. Per-Cluster Phase Advancement

The model can be at Phase 3 for cluster "authentication" while at Phase 1 for cluster "billing". Global phase in `version.json` reflects the minimum phase across all clusters (conservative) or the coverage-weighted mean phase (reported in dashboard).

### Brownfield Mode

#### 1. Per-Chunk Confidence Score

A background process runs after each LoRA round:

1. For each VDB chunk without an up-to-date `model_confidence` score (or score from a stale LoRA version):
   - Generate a test question from the chunk content (using the same LLM)
   - Model attempts to answer from weights (parametric, no retrieval)
   - Measure accuracy: cosine similarity between parametric answer embedding and chunk content embedding
   - Store `model_confidence` and `confidence_lora_version` in chunk payload

```json
// chunk payload additions
{
  "model_confidence": 0.84,
  "confidence_lora_version": 3,
  "chunk_id": "abc123"
}
```

#### 2. Confidence-Gated Routing (query time)

```
query → retrieve top-K chunks → check model_confidence of each chunk
  all K ≥ routing_threshold → parametric
  any K < routing_threshold → retrieval
```

`routing_threshold` starts at 0.85 (conservative) and can be lowered per UC via config as the operator gains confidence in the model.

#### 3. Migration to Greenfield

When `model_confidence ≥ 0.80` for ≥ 70% of VDB chunks, the UC is eligible to transition to greenfield cluster mode. The transition:
1. Runs semantic clustering over existing embeddings
2. Maps existing per-chunk confidence scores to per-cluster initial coverage estimates
3. Switches routing to per-cluster centroid matching

Transition is operator-triggered (not automatic) to preserve control during migration. The trigger is a CLI command `python kvforge.py migrate-to-greenfield --config <uc_config.json>` or a button in KVForge Studio's UC management panel. The system reports migration eligibility (% chunks above confidence floor) in the monitoring dashboard so the operator can make an informed decision.

## Configuration

New per-UC config fields in `DatasourceConfig`:

```json
{
  "deployment_mode": "greenfield",          // "greenfield" | "brownfield" | "auto"
  "prs_weights": {"faq": 0.4, "vdb": 0.4, "realtime": 0.2},
  "prs_auto_weight": true,                  // enable logistic regression weight adaptation
  "prs_stability_window": 3,               // rounds for slope calculation
  "prs_advancement_threshold": 0.72,       // initial per-UC floor (auto-calibrated if null)
  "brownfield_routing_threshold": 0.85,    // initial confidence threshold for brownfield mode
  "realtime_requery_window_minutes": 10,   // window for detecting re-queries (satisfaction proxy)
  "cluster_k_range": [3, 20],              // K search range for silhouette auto-selection
  "min_cluster_samples_for_adaptation": 10 // min labeled queries before weight adaptation runs
}
```

`deployment_mode: "auto"` detects brownfield when existing VDB chunks lack `cluster_id`.

## Data Flow

### Index time (greenfield)
```
Documents → chunk → embed → K-means cluster → store (embedding + cluster_id + metadata) in VDB
                                             → persist centroids to clusters.json
```

### Query time
```
Query → embed → [greenfield] find nearest centroid → route by cluster phase
              → [brownfield] retrieve top-K → check model_confidence → route
              → if retrieval: log (query, answer, cluster_id, timestamp)
```

### LoRA training round
```
Logged real-time queries (weighted by cluster frequency)
+ FAQ set (structured evaluation)
→ LoRA fine-tune
→ vdb_coverage sampling (20 chunks per cluster)
→ per-cluster logistic regression weight update
→ per-cluster PRS recompute
→ advancement check (PRS ≥ threshold AND slope ≥ 0)
→ update version.json cluster state
```

## What Does Not Change

- LoRA training mechanism (`lora_trainer.py`) — same PEFT adapter training, new training data composition
- KV tensor storage and injection (`kv_utils.py`, `kv_indexer.py`) — unchanged
- Replay buffer tier system — unchanged; cluster weighting is additive
- Confidence gate sub-signals (entropy, hedging, query similarity) — unchanged; gate threshold now reads from per-cluster learned threshold
- Base PRS sub-scores (accuracy_ratio, calibration, consistency) — preserved as the `faq_coverage` signal

## Success Criteria

1. New UCs advance phases faster than current baseline without regression in answer quality
2. Per-cluster phase state is visible in the monitoring dashboard
3. Brownfield UCs show measurable parametric coverage growth over time without disrupting existing retrieval
4. PRS weights converge to non-uniform values (proving adaptation is working) within 3–5 LoRA rounds
5. Real-time query logs contribute ≥ 30% of LoRA training data by round 3 for active UCs
