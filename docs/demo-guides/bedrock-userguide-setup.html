What this demo does
Builds a technical documentation RAG system over the AWS Bedrock User Guide. Users can ask questions about Bedrock APIs, model providers, pricing, and integration patterns — and get answers grounded in the official documentation. This demonstrates KVForge for enterprise technical support and internal developer tooling.
📦
Dataset: The AWS Bedrock documentation can be indexed either from a HuggingFace dataset or directly from PDF/HTML source files. The recommended source is psyche/bedrock-user-guide on HuggingFace (a pre-processed text dataset of the Bedrock docs), or the raw PDFs from the AWS documentation site.
🎯
Goal: After setup, questions like "How do I enable model access in Bedrock?", "What models support streaming?", or "What is the Bedrock pricing for Claude Sonnet?" are answered with citations from the official docs.
💡
Use case: Internal developer knowledge bases, documentation chatbots, and automated support ticket triage are all natural applications of this demo pattern.

Alternative: CLI Setup
Index the Bedrock docs from the command line, using either HuggingFace or local PDFs.
Option A — HuggingFace dataset
# 1. Initialize
python kvforge.py init --name bedrock_userguide

# 2. Index via HuggingFace
python -m pipeline.kv_indexer \
  --config datasource_bedrock_userguide.json \
  index hf://psyche/bedrock-user-guide

# 3. Generate FAQs
python -m pipeline.sleep_faq_generator \
  --config datasource_bedrock_userguide.json \
  --output bedrock_faqs.json --count 50

# 4. Train + evaluate
python -m pipeline.lora_trainer \
  --config datasource_bedrock_userguide.json \
  --faqs bedrock_faqs.json

# 5. Query
python -m pipeline.kv_inference \
  --config datasource_bedrock_userguide.json \
  "How do I enable Claude 3 Sonnet in AWS Bedrock?"
Option B — local PDF files
# After downloading bedrock-user-guide.pdf
python -m pipeline.kv_indexer \
  --config datasource_bedrock_userguide.json \
  index ./bedrock-user-guide.pdf
